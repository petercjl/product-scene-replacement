# 场景产品替换

输入是待编辑的场景图和一套指定产品资产。默认处理单张；多张仅在用户明确批量时处理。缺资产时提示可用独立的产品资产生成 Skill 制作，或补齐现有图片的对应说明。处理期间以已选资产版本为准。实际替换固定使用 `@petercjl/sealseek-media-cli` 的 `nano-banana-pro`。

普通任务入口先执行 `node <本 Skill 目录>/.runtime/bin/product-scene-replacement.mjs prepare --json`，进行有界更新检测及本地诊断；源码开发使用包内 bin 入口。父集合管理的安装由所属集合统一更新。安装、更新和恢复遵循包根目录 INSTALL.md / UPDATE.md，执行入口为当前目标自有运行时。

1. **核对资产与场景。** 按 [资产交接协议](references/asset-format.md) 读取清单并验证文件完整性，实际打开所需资产和原场景图。对每张场景记录替换对象、放置锚点、朝向、尺度、接触、遮挡、可见产品面与保护对象。目标、身份或接触条件关键不明确时先澄清。
2. **逐场景挑选证据。** 依据蓝图和说明选择参考图，记录编号、哈希与分工。整体轮廓用全貌；人体接触优先相对尺度；近距离结构或材质优先对应细节。多张参考各自补足实际可见信息。原场景为第一参考，按当前适配器实测的参考数量和排序传入所选资产。只支持两图时第二张选能覆盖关键可见证据的图；覆盖不足则先解决缺口。
3. **逐张生成和验收。** 按 [替换执行与恢复](references/execution.md) 核实 `nano-banana-pro` 的参考能力、费用和授权。每轮从同一原始场景出发，只生成一张。保留构图、人物、姿势、背景、文字、接触遮挡及光影关系。产品可见结构、比例、材质、颜色、标识及连接关系服从选定参考。检查成品与两类原参考，同时通过产品一致性与场景保持即停止。未通过时按实际问题调整提示词或参考，含首轮最多四轮，且受实际预算限制。
4. **交付和恢复。** 每图保留原场景和资产版本、选图理由、逐轮请求与回执、看图验收和结果。批量按场景独立推进，恢复时跳过已通过项目，对未决提交查原任务。交付原图对应结果、轮数和通过或待处理状态。新资产版本需要重新确认受影响范围。

场景图和资产图分别绑定文件标识、哈希与实际查看记录。发现文件描述与当前观察冲突时，单独重开核实。
